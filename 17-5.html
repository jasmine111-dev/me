JavaScript 两种定时器 · 魏鹏

setTimeout（一次性延迟） vs setInterval（周期性重复）— 附 4 个可交互演示 + 对比表

① setTimeout — 延迟一次

在指定毫秒数后只执行一次回调函数，返回一个定时器 ID。

签名：setTimeout(fn, delay, ...args)

// 3 秒后打印一次
var wp_t1 = setTimeout(function() {
    console.log("3 秒到了！");
}, 3000);

// 还没到时间就取消
clearTimeout(wp_t1);

② setInterval — 周期重复

每隔指定毫秒数重复执行回调函数，返回一个定时器 ID。

签名：setInterval(fn, delay, ...args)

// 每隔 1 秒打印一次
var wp_t2 = setInterval(function() {
    console.log("又过了 1 秒");
}, 1000);

// 记得清理！否则永远跑
clearInterval(wp_t2);

📊 两种定时器对比

对比点 setTimeout setInterval
执行次数1 次无限次（直到 clear）
清除方法clearTimeout(id)clearInterval(id)
间隔含义"至少等 N ms 后执行""每隔 N ms 执行一次"
首次延迟有（delay 参数）有（首次也等 delay）
长任务影响串行，下一次等回调跑完再算可能堆积（回调跑 > delay）
典型用途延迟提示、动画一次性、debounce时钟、轮询、进度条、闪烁
模拟对方递归调用自己 = 实现 setInterval—
⚠ Event Loop 里的隐藏坑 ① 实际间隔 ≥ 你写的 delay，因为 JS 单线程、回调要等主线程空闲；
② delay = 0 也不是"立刻执行"，只是把回调扔到宏任务队列末尾；
③ 页面标签页切后台后，setInterval 会被浏览器节流到约 1 次/分钟（省电）。
④ 递归 setTimeout(fn, delay) 比 setInterval 更"精确"——因为上一次执行完才开始算下一次 delay。
